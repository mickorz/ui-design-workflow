# S3 视觉设计（VISUAL）

目标：确定风格、色彩、字体、密度、卡片质感，产出用户确认的视觉规范。

## 提问顺序与决策点

1. **明暗**：浅色 / 深色 / 深浅切换？（汇报投屏几乎总是浅色；深色适合监控大屏与开发者工具）→ visual-style
2. **风格基调**：用词表与用户对齐 → visual-style 的 value
3. **主色**：给 2～3 个候选并说明各自气质 → color
4. **密度**：紧凑 / 舒适 / 宽松 → density
5. **质感**：卡片圆角与阴影、描边风格、留白比例

## 风格词表（value 候选）

| 词 | 气质 | 典型场景 |
|---|---|---|
| light-modern-saas | 现代、干净、企业感 | SaaS 后台、汇报看板 |
| light-minimal | 极简、留白多 | 内容页、作品集 |
| dark-dashboard | 深色监控感 | 监控大屏、运维 |
| corporate-formal | 稳重、传统企业 | 金融、政企 |
| playful-vibrant | 活泼、彩色 | 面向消费者的活动页 |

## 色彩体系

一套完整规范必须包含四组色，缺一项在检查时算 FAIL：

- **主色**：1 个，用于标题强调、主按钮、图表主系列（候选示例：稳重蓝 #2563EB、科技青 #0891B2、商务深绿 #059669）
- **语义色**：成功 / 警告 / 危险 / 中性 4 个；业务有等级时（如严重度）映射到语义色并固定搭配（致命红 #DC2626、严重橙 #EA580C、一般黄 #CA8A04、轻微灰 #6B7280）
- **背景层次**：页面底色、卡片底色、分隔/描边色
- **文字层次**：主文字、次级文字、辅助文字三级灰

## 字体与字号层级

- 字体栈：优先系统字体（system-ui），除非用户指定品牌字体
- 四级字号起步：页面标题 24px / 板块标题 18px / 正文 14px / 辅助 12px；汇报投屏场景整体上调一档
- 行高：正文 1.5～1.6，标题 1.2～1.3

## 信息密度三档

| 档 | 卡片内边距 | 行高节奏 | 适用 |
|---|---|---|---|
| 紧凑 compact | 8～12px | 1.4 | 数据密集的操作台 |
| 舒适 comfortable | 16px | 1.5～1.6 | 汇报看板、常规页面 |
| 宽松 spacious | 24px+ | 1.7 | 落地页、品牌页 |

## 提问方式示例

> 当前阶段：视觉设计。核心问题：主色选哪个？
> A. 稳重蓝 #2563EB（推荐）——汇报场景最稳妥，与语义色冲突最小
> B. 科技青 #0891B2——更有产品感，但与「严重橙」并列时辨识度略降
> C. 商务深绿 #059669——区别于常见蓝色看板，更有辨识度
> 可以直接回复选项，也可以给出现有品牌色。

## 红线

- 语义色全页面统一，不允许每个板块自定义等级配色
- 视觉规范必须落到可实现的值（色值、px），不允许只写「蓝色调」「大一点」
