# S2 信息架构（STRUCTURE）与 S5 数据规范（DATA）

## S2 信息架构

目标：确定页面数量、板块划分、内容层级与导航方式，产出页面结构方案。

### 页面数量判断

单页面（one-page）适用于：内容一屏流可讲完、受众快速浏览、无用户间状态差异（典型：汇报看板、落地页、活动页）。
多页面适用于：不同角色看不同内容、内容量超过 3 屏且板块间无连续性、需要独立 URL 分享。
不确定时给两个方案让用户选，附推荐理由。

### 常见页面骨架模式（板块划分的起点）

| 模式 | 骨架 | 适用 |
|---|---|---|
| 汇报看板 | 页头 → 概览指标/图表 → 分析区 → 明细清单 | 高层汇报、监控 |
| 操作台 | 侧边导航 → 工具栏 → 主工作区 → 详情侧栏 | 后台管理、编辑器 |
| 内容页 | 页头 → 正文流 → 相关内容 | 文章、详情 |
| 表单页 | 标题 → 分步/分区表单 → 提交区 | 注册、配置向导 |
| 落地页 | 首屏主张 → 特性区块 → 行动号召 | 产品宣传 |

从最接近的模式出发做增删，向用户复述「页面从上到下是：A → B → C」，确认后形成 module-set 决策。

### 内容层级与导航

- 层级一般三级：页面标题 → 板块标题 → 卡片/条目；超过三级说明结构有问题，回去合并板块
- 单页面导航：锚点目录（板块多于一屏时建议）；多页面导航：顶部/侧边导航，需确认选中态与顺序
- 每个板块必须能一句话回答「这一板块让用户知道什么」，答不出就删

### 输出

页面结构方案：骨架模式 + 板块顺序清单 + 层级树 + 导航方式。用户确认后登记 layout、module-set、navigation 决策。

## S5 数据与技术规范（DATA）

目标：数据从哪来、长什么样、怎么算，跑在什么环境。

### 数据来源决策

| 来源 | 适用 | 对设计的影响 |
|---|---|---|
| 静态文件（JSON/CSV） | 汇报、演示、原型 | 无后端依赖，加载失败要有提示 |
| 后端接口 | 真实产品页面 | 需约定接口边界与字段，错误态设计 |
| 页内写死 | 极简演示 | 数据变更需改代码，不推荐 |

### 字段与口径（缺一不可）

- 每个板块列出它消费的字段：名称、类型、单位、取值枚举
- 每个统计数字写清口径（「遗留 = 已提出未关闭」「趋势按自然月聚合」）
- 枚举值封闭列出（severity: fatal/serious/minor/trivial），不允许「等等」
- 产出 data-model、data-source、data-scope 决策，写入 design.md 第 9 章

### 技术约束

确认：目标形态（静态 HTML / 框架页面）、依赖（图表库、字体、CDN）、浏览器范围、性能要求、可访问性要求。
产出 tech-constraint 决策，写入第 11 章。本 Skill 不写实现代码，技术约束只到「形态与依赖」粒度。
