# 案例输入：PRD 质量数据看板

> ui-design 的 Benchmark 输入（T5 对照评测用）。模拟用户首次提出的模糊需求。
> 运行 ui-design 时应通过多轮问答补全设计中缺失的决策，输入中已明确的要求
> 应直接登记为已确认决策，不得重复提问。

## 用户原始需求

我需要给领导做一个 PRD 质量的数据看板页面，汇报这个月产品需求文档的质量情况。

要求：

- 单页面，从上往下滚动就能看完
- 现代简洁的浅色风格，别太花哨
- 信息密度舒适一点，不要挤在一起
- 要有图表能看质量趋势
- 要有风险分析，让人一眼看出哪些模块问题多
- 要有 TOP 5 典型问题
- 要有完整的问题清单，方便领导问到哪个就能查到哪个
- 不需要任何裁决或者处理问题的功能，只看不操作
- 最终要能生成一个 HTML 页面，数据先用静态的

## 备注

- 对照基准：与人工讨论得到的 dashboard 设计方案对比（T5），检查受众、布局、
  风格、密度、板块构成、禁止项、技术目标等关键决策是否完整保留
- 本案例同时验证：输入中已明确要求不重复提问；后期修改早期决策时做影响分析
