## 脚本能力（四维检查的自动化边界）

| 维度 | 自动检查项 |
|---|---|
| 结构完整性 | 13 章齐全且顺序正确、每章状态标记齐全且不为 pending、已确认段有真实内容（排除注释占位）、frontmatter 字段合法、frozen 与 status 一致 |
| 决策完整性 | session 存在且可解析、pending 清空、无 confirmed+source=ai、superseded 指向存在的 confirmed 决策、ID 格式与唯一性、session/design 冻结一致、第 13 章决策表与 session 逐 ID 对账（含 superseded 标注） |
| 数据完整性 | 第 9 章已确认且非空；来源/字段/口径语义列入人工复核项 |
| 交互完整性 | 第 8 章已确认且非空；异常态覆盖列入人工复核项 |

- 未确认事项 = partial 章节数 + 章节待确认条目数 + session pending 数；READY_FOR_REVIEW 要求四维 PASS 且未确认事项为 0
- 检查通过不自动冻结（脚本输出 READY_FOR_REVIEW，冻结仍走 S7 用户确认），符合计划 6.5 节
- exit code：READY_FOR_REVIEW 为 0，FAILED 为 1，可被 CI 或 Agent 直接消费

## 关键设计决策

1. **标准库优先，PyYAML 可用则优先**：脚本内置了一个覆盖本项目 frontmatter 语法的 YAML 子集解析器（嵌套映射、对象序列、内联列表、引号、行内注释），无 PyYAML 环境也能跑；有 PyYAML 时自动切换。两路解析器在三份 session 文件上与 PyYAML 逐字段对拍一致，且自检中加入不依赖 PyYAML 的回退解析器结构断言。
2. **语义检查不冒充自动检查**：数据口径、字段含义、异常态覆盖等语义项明确列为「人工复核项」输出，脚本只把结构可判定的事实作为 PASS/FAIL，避免假阳性。
3. **负向用例从正向案例程序化注入缺陷**：保证坏文档与好文档只有被测差异，测试失效风险最低。
